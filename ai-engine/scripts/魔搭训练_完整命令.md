### 0.1 先补两条忽略规则（否则会推上去不该推的）

实测本项目的 `.gitignore`（临时仓库探针）：

```
会被提交： ai-engine/models/test-coco-yolo11n/best.pt   ← 5.35 MB 权重（不该推）
```

```gitignore

ai-engine/models/**/*.pt
```

（`train.py` 才 13 KB，粘一次能接受；6 个文件都这么干就太笨了。）

## 块 0.5 ── 魔搭：选镜像（创建实例时）

预装镜像列表里选：

**首选 `ubuntu22.04-cuda12.1.0-py310-torch2.3.0-1.18.0`**
（想用更新的 Python 则选 `ubuntu22.04-cuda12.1.0-py312-torch2.3.1-tf2.16.1-…`）

理由：

| 因素 | 说明 |
|---|---|
| **CUDA 12.1** | 对驱动要求低（驱动 ≥ 525 即可，几乎任何机器都满足）。**CUDA 13.0 需要很新的驱动** —— 宿主驱动偏旧时 `torch.cuda.is_available()` 会是 `False`，你就在 CPU 上训练而不自知 |
| **torch 2.3** | 完全在 ultralytics 的支持范围内，是 CUDA 12.1 的成熟搭配 |
| **py310** | 三方包兼容性最稳的版本（py312 也可用，只是保守起见选 310） |

**不要选**：

- `ubuntu20.04-cuda11.7.1-py38-torch2.0.1-…` 与 `ubuntu20.04-cuda11.3.0-py37-torch1.11.0-…`
  —— Python 3.7/3.8 与 torch 太旧，新版 ultralytics 会要求更高版本，容易陷进依赖冲突；
- `…paddle3.0.0-…` —— 与本任务无关。

**选完立刻花 10 秒验证**（不行就换镜像重开实例，成本很低）：

```bash
nvidia-smi
python -c "import torch;print(torch.__version__, torch.version.cuda, torch.cuda.is_available())"
# 期望：2.3.x  12.1  True
# 若 cuda.is_available() 是 False —— 别开始训练，换镜像或换实例
```

> **实测环境**（2026-09-25，本项目实例，选的是第 2 个镜像）：
>
> ```
> NVIDIA-SMI 550.54.15   Driver Version: 550.54.15   CUDA Version: 12.4
> NVIDIA A10   23028MiB (24GB)
> torch 2.3.1+cu121   12.1   True
> ```
>
> 这条实测正好印证了上面的判断：**驱动 550 最高只支持到 CUDA 12.4，
> 而 CUDA 13 需要驱动 ≥ 580** —— 所以截图里预选的第 1 个镜像
> （`cuda13.0.3-py312-torch2.13.0`）在这台机器上会 `is_available() = False`，
> 你会安安静静地在 CPU 上训练。**选镜像时先看 `nvidia-smi` 的驱动版本上限。**

> ⚠️ **别让 pip 把镜像里预装的 torch 换掉。** `pip install -U ultralytics` 只会看到
> torch 已满足要求而不动它；但**不要执行 `pip install -U torch`** ——
> 那会装上 PyPI 的通用 wheel，可能破坏与 CUDA 的匹配。装完后用上面那条命令复查一次。

**额度**：创建页显示"剩余额度 36 小时"。24G 显存跑 yolo11n@640，几千张图训 100 轮
约 1~2 小时 —— 额度够用，但别耗在无意义试跑上：块 5 的链路验证固定用 `--epochs 3`。

### ② ultralytics 自带字体：验证集预测图的检测框标签（**漏了会训练失败**）

`ultralytics/data/utils.py` 里有个 `check_font()`：当类别名含非 ASCII 字符时
（**我们的 19 类全是中文 → `is_ascii()` 为 `False`**），它会去要 `Arial.Unicode.ttf`，
而查找范围**只有 `USER_CONFIG_DIR`（即 `/root/.config/Ultralytics/`）**，
找不到就从 `ultralytics.com` / `github.com` 下载。

⚠️ **魔搭上 `github.com` 不通，这一步下载失败是【致命】的**（见块 5）。
上面 `apt install fonts-noto-cjk` **满足不了它** —— 那个字体装进了系统目录，
但不在 ultralytics 的查找范围里。必须手工放进去：

```bash
mkdir -p /root/.config/Ultralytics
for F in Arial.Unicode.ttf Arial.ttf; do
  curl -fL -o /root/.config/Ultralytics/$F \
    https://gh-proxy.com/https://github.com/ultralytics/assets/releases/download/v0.0.0/$F
done
ls -l /root/.config/Ultralytics/     # Arial.Unicode.ttf=23278008，Arial.ttf=773236
```

> **为什么走 `gh-proxy.com`**：实测魔搭上 `github.com` 连接超时，`gh-proxy.com` 可用。
> 预训练权重 `yolo11*.pt` 也在同一批 GitHub releases 下，同样要靠它 —— 见块 6。

自查（已放好则**秒过，不会触发任何下载**）：

```bash
python -c "
from ultralytics.utils.checks import check_font, USER_CONFIG_DIR
print('配置目录:', USER_CONFIG_DIR)
check_font('Arial.Unicode.ttf')
print('字体检查通过')
"
```

## 块 4.5 ── 还没有数据集？先用现成测试图验证链路（约 10 分钟）

正式数据集要等项目后期才到位。**不要等数据来了才第一次跑训练脚本** ——
那时才发现 GPU 路径有问题，代价是几小时额度加一次失败训练。

`smoke_test.py` 用仓库自带的 3 张测试图（`ai-engine/tests/*.jpg`）造一个最小数据集，
把 `prepare_dataset → train → evaluate` 整条链路走一遍，一次暴露环境、依赖、
参数、产物的问题。**只用 10 分钟额度。**

```bash
cd /mnt/workspace/wildlife
python smoke_test.py --keep
```

它检查 5 件事，全部 PASS 才算链路通：

| 检查项 | 通过标准 |
|---|---|
| `prepare_dataset.py` | 数据校验通过并生成 `data.yaml` |
| `train.py` | `--device auto` **解析成 GPU**（不是静默退回 cpu） |
| 产出 `best.pt` | 文件存在且非空 |
| `evaluate.py` | 生成 `meta.json` |
| `meta.json` 可溯源 | `metricsVerified=true` 且有 `weightsMd5`，`environment.gpuName` 记到显卡名 |

结尾会打印 PASS/FAIL 汇总。**若 `--device` 那一项显示 `cpu` 而机器有显卡**，
说明 torch 没识别到 GPU —— 先回去查 `torch.cuda.is_available()`，别继续。

> ⚠️ 这次跑出来的精度**毫无意义**（3 张图、3 轮、imgsz 320），
> 脚本自己也会这么提示。它只验"链路通不通"，绝不能拿这个 mAP 写进论文。

## 块 4.6 ── **长训练前必做：把数据集拷到本地盘**（否则慢 10 倍）

NAS（`/mnt/data`）IO 慢，直接在上面训练实测 **4.8 s/it、每 epoch 20 分钟**，
100 epochs 要 33 小时，**会耗尽 GPU 额度**。拷到 `/tmp`（实例本地盘）后
约 **0.5-1 s/it、每 epoch 2-3 分钟**，100 epochs 仅 4-5 小时。

```bash
mkdir -p /tmp/yolo
cp -r /mnt/data/wildlife-combined/yolo/* /tmp/yolo/

# ⚠️ 改 path 不要用 sed —— data.yaml 里的 path 带引号：
#      path: "/mnt/data/wildlife-combined/yolo"
#    sed 's|path: /mnt/...|' 少了引号，匹配不上且不报错（静默失效）。
python - <<'PY'
import pathlib
p = pathlib.Path("/tmp/yolo/data.yaml")
text = p.read_text(encoding="utf-8").replace(
    '"/mnt/data/wildlife-combined/yolo"', '"/tmp/yolo"'
).replace("/mnt/data/wildlife-combined/yolo", "/tmp/yolo")
p.write_text(text, encoding="utf-8")
print(text[:80])
PY

# 亲眼确认 + 核对拷贝完整
head -3 /tmp/yolo/data.yaml              # 必须是 path: "/tmp/yolo"
for s in train val; do
  echo "$s: 图 $(ls /tmp/yolo/images/$s | wc -l)  标 $(ls /tmp/yolo/labels/$s | wc -l)"
done
df -h /tmp | tail -1                      # 本地盘剩余 > 20 GB
```

**实测效果**（同一份数据、同一台 A10、yolo11s、batch=32）：

| 数据位置 | 读取速度 | 每步 | 每 epoch（493 步） | 100 epochs |
|---|---|---|---|---|
| `/mnt/data`（NAS） | — | 4.8 s | ~20 min | **~33 小时** ❌ 超额度 |
| `/tmp`（本地盘） | **782 MB/s** | **~0.44 s** | **~3.6 分钟** | **~6 小时** ✅ |

> ⚠️ **上一版文档这里写的是「0.12 s/步、~2 小时跑完 100 轮」，实测偏乐观约 4 倍。**
> 以本项目 yolo11s / 19,723 张 / batch 32 / 8 核 / A10 的实测为准：
> 稳定态 **~216 秒/epoch**，60 轮耗时约 **3.6 小时**。
>
> **关键结论：换模型几乎不影响 epoch 耗时。** 实测 yolo11n 反而更慢（283 s/epoch），
> yolo11s 是 216 s/epoch —— 因为**瓶颈在 CPU 侧的 JPEG 解码与 mosaic 增强**
> （每轮要解码约 63,000 张图的副本），**不是 GPU 算力**。
> 所以调 `--workers` 比换模型更有效：`4 → 6` 实测提速约 15%，8 核是上限。

> ⚠️ **NAS 只用来存数据，不用来训数据。** 实例一旦关闭 `/tmp` 内容即丢失，
> 但 `/mnt/data` 的原始数据集还在，重开实例再拷一次即可（几分钟）。
> **改完 `path` 后一定要看 `s/it` 是否 < 0.6 秒** —— 实测本地盘约 0.44 秒；
> 若显示 4-5 秒，说明 path 没改成功，训练仍在 NAS 上读。

登记版本到数据库（**注意 `--api-base` 必须写 `http://backend:8085`**：
在 ai-engine 容器里 `localhost` 指的是容器自己，不是后端容器）：

> ⚠️ **`wildlife-v1.0` 这一行已经由 `docker/mysql/init.sql` 建库时预置了**
> （`model_version` 表的 `version` 列上有 `UNIQUE KEY uk_model_version`），
> 而 `register_model.py` 走的是 **POST `/api/models`** = `ModelService.create()` = 纯 INSERT。
> **对已存在的版本再 POST 会撞唯一约束抛 `DuplicateKeyException`，
> 后端只捕获 `IllegalArgumentException`，所以直接返回 HTTP 500。**
>
> 另外 `init.sql` 预置的是**占位内容**：`model_name='Wildlife YOLO'`、
> `class_config` 是 20 类的旧清单、指标字段全空 —— 必须覆盖成真实值。
>
> **所以正式版本要更新而不是新建，用 `PUT /api/models/1`**（先 `GET /api/models` 查 id）：

```powershell
# 用 PUT 更新已存在的版本行（把真实 meta.json 覆盖进去）
$tok = (Get-Content "$env:TEMP\token.txt" -Raw).Trim()
$body = @{
    modelName      = 'wildlife-v1.0'
    classConfig    = (Get-Content 'ai-engine\models\wildlife-v1.0\classes.txt' -Raw |
                      ConvertFrom-Json)   # 见下方说明
    precisionValue = 0.8495
    recallValue    = 0.7340
    map50          = 0.8106
    map5095        = 0.6357
    status         = 'ENABLED'
    modelPath      = '/models/wildlife-v1.0/best.pt'
} | ConvertTo-Json -Depth 5
Invoke-RestMethod -Method Put -Uri 'http://localhost:8085/api/models/1' `
    -Headers @{ 'X-Auth-Token' = $tok } `
    -ContentType 'application/json; charset=utf-8' `
    -Body ([System.Text.Encoding]::UTF8.GetBytes($body))
```

> **为什么不用 `curl.exe -d` 发中文 JSON**：PowerShell 里 `curl.exe -d '{...}'`
> 会**吃掉内层双引号**，后端收到 `{"classConfig": [野猪, ...]}` 这种畸形 JSON，
> 报 `HttpMessageNotReadableException: JSON parse error: Unexpected character ('i' (code 105))`。
> **用 `Invoke-RestMethod` + `UTF8.GetBytes()`**，或 `curl.exe -d "@文件"` 从文件读。
>
> 上面 `classConfig` 的三行写法只是示意 —— 真实值是 **19 个中文类别名的 JSON 数组**，
> 直接从 `meta.json` 的 `classNames` 字段取最稳妥。

`register_model.py` 仍可用于**登记一个全新的版本号**（那时 POST 不冲突）：

```powershell

```

上面只打印请求体，不发送。核对无误后加 `--send` 真正发送：

```powershell

    --meta /models/wildlife-v1.0/meta.json `
    --version wildlife-v1.1 `
    --model-path /models/wildlife-v1.1/best.pt `
    --api-base http://backend:8085 `

```

**权重一致性告警条消失**（说明"页面显示的版本"与"实际加载的权重"终于一致）。
