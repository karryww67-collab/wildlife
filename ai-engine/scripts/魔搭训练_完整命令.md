## 块 0 ── 本机：把代码推到一个 git 仓库（推荐）

**为什么不用"手工传 6 个文件"**：魔搭实例关闭后除 `.ipynb` 全丢（见开头），
每次重开实例都要重新准备代码。手工传 6 个文件是**每次**都要做，
`git clone` 只要**一条命令** —— 有了 git 就该走这条路。

本机 git 装在 `D:\Git`（不在 PATH 里），所以下面用绝对路径 `$git`。

### 0.1 先补两条忽略规则（否则会推上去不该推的）

实测本项目的 `.gitignore`（临时仓库探针）：

```
会被提交： ai-engine/models/test-coco-yolo11n/best.pt   ← 5.35 MB 权重（不该推）
          .workbuddy/tmp/...                          ← 9.1 MB 临时文件（不该推）
被忽略：   ai-engine/data/  ✅ 439 张图 144.6 MB —— 安全，不会推上去
```

原因是 `.gitignore` 里的 `models/*.pt` 带中间斜杠，**只匹配根目录**的 `models/`；
而 `data/` 没有前导斜杠，因此匹配任意层级的 `data` 目录 ✅。

往 `.gitignore` 末尾追加两行：

```gitignore
# 训练/工作产物（由 .workbuddy/ 与 ai-engine/models/ 下产生）
.workbuddy/
ai-engine/models/**/*.pt
```

### 0.2 init + 提交 + 推远端

```powershell
$git = 'D:\Git\cmd\git.exe'
cd 'D:\毕设\代码\wildlife'

& $git init
& $git add -A

# 提交前先核对：条目数应在 200 左右，且下面这条**必须为空**
(& $git status --short | Measure-Object).Count
& $git status --short | Select-String '\.pt$|\.jpg$|node_modules|\.workbuddy'

& $git commit -m "野生动物图像批量识别系统：完整实现"
```

在 GitHub / Gitee 网页上建一个**私有仓库**（论文项目，别公开），然后：

```powershell
& $git remote add origin https://github.com/<用户名>/<仓库名>.git
& $git branch -M main
& $git push -u origin main
```

私有仓库 push 时需要 **token**（不是登录密码）。

### 0.3 以后再加代码，都是一条命令

```powershell
& $git add -A; & $git commit -m "说明"; & $git push
```

## 块 0.9 ── 备用：不用 git 的两种上传方式

**方式一（最简单）**：JupyterLab 左侧文件浏览器支持**多选/拖拽上传**，
6 个文件合计约 47 KB，一次拖进去即可：

```powershell
cd 'D:\毕设\代码\wildlife'
Get-ChildItem ai-engine\check_weights.py, `
    ai-engine\scripts\prepare_dataset.py, `
    ai-engine\scripts\train.py, `
    ai-engine\scripts\evaluate.py, `
    ai-engine\scripts\register_model.py, `
    ai-engine\models\wildlife-v1.0\classes.txt | Select-Object Name, Length
```

注意**上传目标是 `/mnt/workspace/wildlife/`**（先 `mkdir -p` 并在文件浏览器里切到该目录），
不是默认的 `/mnt/workspace` —— 否则后面 `cd /mnt/workspace/wildlife && python train.py` 会找不到文件。

**方式二**：若只有单个文件出问题，可在 Notebook 里新建 cell 用魔法命令直接写：

```python
%%writefile train.py
# ...把本机 ai-engine/scripts/train.py 的内容粘进来...
```

（`train.py` 才 13 KB，粘一次能接受；6 个文件都这么干就太笨了。）

## 块 0.5 ── 魔搭：选镜像（创建实例时）

预装镜像列表里选：

**首选 `ubuntu22.04-cuda12.1.0-py310-torch2.3.0-1.18.0`**
（想用更新的 Python 则选 `ubuntu22.04-cuda12.1.0-py312-torch2.3.1-tf2.16.1-…`）

理由：

| 因素 | 说明 |
|---|---|
| **CUDA 12.1** | 对驱动要求低（驱动 ≥ 525 即可，几乎任何机器都满足）。**CUDA 13.0 需要很新的驱动** —— 宿主驱动偏旧时 `torch.cuda.is_available()` 会是 `False`，你就在 CPU 上训练而不自知 |
| **torch 2.3** | 完全在 ultralytics 的支持范围内，是 CUDA 12.1 的成熟搭配 |
| **py310** | 三方包兼容性最稳的版本（py312 也可用，只是保守起见选 310） |

**不要选**：

- `ubuntu20.04-cuda11.7.1-py38-torch2.0.1-…` 与 `ubuntu20.04-cuda11.3.0-py37-torch1.11.0-…`
  —— Python 3.7/3.8 与 torch 太旧，新版 ultralytics 会要求更高版本，容易陷进依赖冲突；
- `…paddle3.0.0-…` —— 与本任务无关。

**选完立刻花 10 秒验证**（不行就换镜像重开实例，成本很低）：

```bash
nvidia-smi
python -c "import torch;print(torch.__version__, torch.version.cuda, torch.cuda.is_available())"
# 期望：2.3.x  12.1  True
# 若 cuda.is_available() 是 False —— 别开始训练，换镜像或换实例
```

> ⚠️ **别让 pip 把镜像里预装的 torch 换掉。** `pip install -U ultralytics` 只会看到
> torch 已满足要求而不动它；但**不要执行 `pip install -U torch`** ——
> 那会装上 PyPI 的通用 wheel，可能破坏与 CUDA 的匹配。装完后用上面那条命令复查一次。

**额度**：创建页显示"剩余额度 36 小时"。24G 显存跑 yolo11n@640，几千张图训 100 轮
约 1~2 小时 —— 额度够用，但别耗在无意义试跑上：块 5 的链路验证固定用 `--epochs 3`。

判读：

| 结果 | 怎么办 |
|---|---|

```
UserWarning: Glyph 37326 (\N{CJK UNIFIED IDEOGRAPH-91CE}) missing from font(s) DejaVu Sans.
```

```bash
# Debian/Ubuntu
```

## 块 6 ── 魔搭：正式训练

```bash
cd /mnt/workspace/wildlife
mkdir -p /mnt/workspace/out
python train.py \
    --data /mnt/workspace/data/wildlife/data.yaml \
    --model yolo11n.pt \
    --epochs 100 --imgsz 640 --workers 4 \
    --patience 50 --save-period 10 \
    --name wildlife-v1.0 --project /mnt/workspace/runs \
    2>&1 | tee /mnt/workspace/out/train-wildlife-v1.0.log
```

换更大的模型（24 GB 显存参考）：`--model yolo11s.pt` 或 `--model yolo11m.pt`。

中断后续训（`last.pt` 每轮都会更新）：

```bash
python train.py \
    --data /mnt/workspace/data/wildlife/data.yaml \
    --name wildlife-v1.0 --project /mnt/workspace/runs --resume
```

**长训练别等结束才取产物** —— 每训一段就把 `runs/wildlife-v1.0/weights/last.pt`
取回一次，实例被回收时才能续训而不是从第 1 轮重来。

## 块 7 ── 魔搭：评测并生成可溯源的 meta.json

```bash
cd /mnt/workspace/wildlife
mkdir -p /mnt/workspace/out/wildlife-v1.0
python evaluate.py \
    --weights /mnt/workspace/runs/wildlife-v1.0/weights/best.pt \
    --data /mnt/workspace/data/wildlife/data.yaml \
    --out /mnt/workspace/out/wildlife-v1.0/meta.json \
    --write-classes
```

打印关键信息（**记下 `weightsMd5`，块 9 要用它核对权重没传坏**）：

```bash
python -c "
import json
m = json.load(open('/mnt/workspace/out/wildlife-v1.0/meta.json', encoding='utf-8'))
print('metricsVerified :', m['metricsVerified'])
print('mAP50 / mAP50-95:', m['map50'], '/', m['map5095'])
print('Precision/Recall:', m['precisionValue'], '/', m['recallValue'])
print('weightsMd5      :', m['weightsMd5'])
print('gpu             :', m['environment']['gpuName'], m['environment']['gpuMemoryMB'], 'MB')
print('batch / imgsz   :', m['batch'], '/', m['imgsz'])
"
```

`metricsVerified` 必须是 `True` —— 它表示"这组数字来自一次可复现的评测"。
若为 `False`，说明 meta.json 不是 `evaluate.py` 写出来的，指标不可溯源。

## 块 9 ── 本机：落地并确认不再回退

本机 PowerShell，在项目根目录：

```powershell
cd 'D:\毕设\代码\wildlife'

# 先设成你下载文件所在的目录
$DL = "$env:USERPROFILE\Downloads"

# 1) 放进版本目录
Copy-Item "$DL\best.pt"     ai-engine\models\wildlife-v1.0\best.pt     -Force
Copy-Item "$DL\classes.txt" ai-engine\models\wildlife-v1.0\classes.txt -Force
Copy-Item "$DL\meta.json"   ai-engine\models\wildlife-v1.0\meta.json   -Force

# 2) 核对权重 md5，必须与块 7 打印的 weightsMd5 一致（大小写不敏感）
(Get-FileHash ai-engine\models\wildlife-v1.0\best.pt -Algorithm MD5).Hash

# 3) 体检：期望看到「回退到备用权重: 否」
docker exec wildlife-ai-engine python check_weights.py wildlife-v1.0
```

把引擎指回正式版本 —— 改 `docker-compose.yml` 的 ai-engine 段两行：

```yaml
      ACTIVE_MODEL_VERSION: wildlife-v1.0
      YOLO_MODEL_PATH: /models/wildlife-v1.0/best.pt
```

```powershell
# 4) 重启生效
docker compose up -d

# 5) 自检接口：期望 ok=true、usingFallback=false
curl.exe -s "http://localhost:9095/ai/model/status?version=wildlife-v1.0"

# 6) 体检确认（此时引擎已在跑正式版本）
docker exec wildlife-ai-engine python check_weights.py --all
```

登记版本到数据库（**注意 `--api-base` 必须写 `http://backend:8085`**：
在 ai-engine 容器里 `localhost` 指的是容器自己，不是后端容器）：

```powershell
docker cp ai-engine\scripts\register_model.py wildlife-ai-engine:/tmp/
docker exec wildlife-ai-engine python /tmp/register_model.py `
    --meta /models/wildlife-v1.0/meta.json `
    --version wildlife-v1.0 `
    --model-path /models/wildlife-v1.0/best.pt `
    --api-base http://backend:8085
```

上面只打印请求体，不发送。核对无误后加 `--send` 真正发送（需管理员 token）：

```powershell
# 取管理员 token
$tmp = "$env:TEMP\login.json"
'{"username":"admin","password":"admin123"}' | Set-Content $tmp -Encoding ascii
$token = (((curl.exe -s -X POST 'http://localhost:8085/api/auth/login' `
    -H 'Content-Type: application/json' --data-binary "@$tmp") -join '') | ConvertFrom-Json).token

docker exec wildlife-ai-engine python /tmp/register_model.py `
    --meta /models/wildlife-v1.0/meta.json `
    --version wildlife-v1.0 `
    --model-path /models/wildlife-v1.0/best.pt `
    --api-base http://backend:8085 `
    --send --token $token
```

最后在「模型管理」页把 `wildlife-v1.0` 启用，并确认页面上的
**权重一致性告警条消失**（说明"页面显示的版本"与"实际加载的权重"终于一致）。
