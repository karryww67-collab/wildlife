> `ai-engine/scripts/prepare_dataset.py` 的**实际校验逻辑**，不是建议值 ——
> 不符合的部分会被它拦下来（退出码 1）。

## 1. 目录结构（硬性）

```
<数据集根>/
├── images/
│   ├── train/   *.jpg
│   └── val/     *.jpg
└── labels/
    ├── train/   *.txt      ← 与图片**同名**（仅扩展名不同）
    └── val/     *.txt
```

- 允许的图片扩展名：`.jpg .jpeg .png .bmp .webp .tif .tiff`（建议统一 `.jpg`）
- 标注文件名必须与图片**同名**：`images/train/0001.jpg` ↔ `labels/train/0001.txt`
- **只有 `train` 与 `val` 两个 split**（`--splits` 可改，但训练脚本默认这两个）
- 建议图片短边 ≥ 640px（训练用 `--imgsz 640`，太小的图会被放大）

## 2. 标注格式（硬性）

每个 `.txt` 每行一个目标，**恰好 5 个字段，空格分隔**：

```
class_id  cx  cy  w  h
```

| 字段 | 含义 | 约束 |
|---|---|---|
| `class_id` | 类别编号，**从 0 开始** | `0 ≤ id < 类别总数`，越界直接报错 |
| `cx` `cy` | 框中心点，相对图片宽高 | **归一化到 0~1**（不是像素！） |
| `w` `h` | 框宽高，相对图片宽高 | 归一化 0~1，且必须 > 0 |

- 归一化 = 像素值 ÷ 图片宽（或高）。写成像素坐标会被判为"坐标未归一化"
- 无目标的图片**可以不放 `.txt`** —— 这是合法的负样本
- **反过来不行**：有 `.txt` 却没有对应图片 → 报"孤立标注"

## 3. 类别清单（classes.txt）

一行一个类别名，**行序即 `class_id`**。

```
大熊猫     ← class_id = 0
雪豹       ← class_id = 1
川金丝猴   ← class_id = 2
...
```

> ⚠️ **顺序错了不会报错，但模型学到的是错的映射，训练全程静默。**
> `prepare_dataset.py` 的源码里专门写了这句警告。

### 两条路线，二选一

**路线 A（本项目已采用 ✅）：按找到的数据反推类别表。**
你找到什么数据集，就把 `classes.txt` 写成它的类别。改两处即可：
`ai-engine/models/<版本>/classes.txt` 与数据库 `model_version.class_config`。

> 本项目即按此路线执行：用 SWG（14 类）与 WCS（11 类）的**并集**，
> 跨数据集同名物种合并、近缘种按属归并，得到 **19 类**。
> 论文里把"类别体系可配置"作为设计点写出来 ——
> 系统本来就是这么设计的（`class_config` + 版本目录各自带 `classes.txt`）。

**路线 B（已放弃）：坚持最初设想的 20 个中国特有种。**
代价：公开数据集极少同时覆盖这 20 类，需要多源拼接 + 自己做类别归并映射，
工期不可控。而且**麂/鹿/羚这一组（小麂、赤麂、毛冠鹿、中华鬣羚、斑羚）
连人眼都难区分**，硬训这 20 类的 mAP 会很难看，答辩时反而是减分项。
本项目实际执行时确认：雪豹、小熊猫、小麂、毛冠鹿、斑羚、红腹角雉、血雉、
绿尾虹雉这 8 类在公开渠道**确实没有任何带框数据**（已穷尽核查 LILA 全球目录、
HuggingFace、ScienceDB、ModelScope、Gitee、OpenDataLab）。

## 4. 数量（建议值）

| 指标 | 最低 | 推荐 | 说明 |
|---|---|---|---|
| 总图片数 | 2,000 | **3,000 ~ 5,000** | 毕设规模够用且训得动 |
| 每类训练实例（框数） | 200 | 500+ | **少于 100 的类别建议合并或删掉** |
| val 每类实例 | 20 | 50+ | val 太少指标波动极大 |
| 负样本（无目标图） | — | ≤ 10% | 太多会拉低召回 |
| train : val | 8:2 | 8:2 或 9:1 | 按**图片**划分，不要按框 |

> 零实例的类别要在 `classes.txt` 里去掉 —— 它的 mAP 恒为 0，只会拉低整体指标。
> `prepare_dataset.py` 会把这类类别单独列出来提醒你。

## 5. 找数据时必须确认的 5 件事

按重要性排序，**第 1 条是最大的坑**：

1. **必须有「物种级边界框」，不是图片级分类标签。**
   红外相机数据集绝大多数只有"这张图是鹿"的**分类标签**，没有框。
   更常见的陷阱：只有 MegaDetector 的框，而它只分 `animal / person / vehicle`
   **三个类**，不是物种 —— 拿它训不出物种检测。
   → 搜数据时关键词必须带 `object detection` / `bounding box` / `YOLO format`。
2. **标注完整**：一张图里多个个体都要有框，不能只标一个。
3. **框不要越界**：`cx±w/2` 必须在 0~1 内（贴着边缘裁切的框容易被判非法）。
4. **别混入"人/车"以外的干扰类**（除非你想把 `person` 也当一个类）。
5. **授权可用**：毕设论文里要写明数据来源与许可（CC-BY / 研究用途等）。

## 6. 拿到数据后的验收

```bash
cd /mnt/workspace/wildlife
python prepare_dataset.py \
    --dataset /mnt/workspace/data/wildlife \
    --classes /mnt/workspace/wildlife/classes.txt \
    --out /mnt/workspace/data/wildlife/data.yaml
echo "退出码=$?   # 0=通过；1=数据有问题，先修数据别硬训"
```

它会报告：图片/标注配对情况、孤立标注、非法行（含具体文件名与行号）、
每个类别的实例数与占比、**未出现任何实例的类别**。

`data.yaml` **由它生成，你不用手写**。

## 7. 数据到位后的完整顺序

```
块 4    prepare_dataset.py      校验数据 + 生成 data.yaml
块 4.5  smoke_test.py           先用 3 张测试图验证链路（可选，10 分钟）
块 5    train.py --epochs 3     用真数据跑 3 轮验证
块 6    train.py --epochs 100   正式训练
块 7    evaluate.py             生成 metricsVerified=true 的 meta.json
块 8    关闭实例前下载 best.pt + meta.json + classes.txt
```
